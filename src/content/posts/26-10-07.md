## 一、学习笔记

### 1. 模型权重与开放方式

#### 基本概念

> **模型权重**：模型在训练过程中学到的数值参数，通常以大型张量或矩阵保存。

权重承载学到的规律；运行模型还需要**模型架构、推理程序、分词器**等配套组件。可以用"训练后的存档"帮助理解，但权重并不是逐条储存知识的数据库。

- **训练**：利用数据和优化算法调整模型参数的过程。
- **推理**：使用训练后的模型处理输入、产生输出的过程。

| 开放方式 | 获得的内容 | 能进行的操作 |
|---|---|---|
| 公开论文 | 架构、方法与实验说明 | 理解设计；不一定能复现训练或运行模型 |
| 提供 API | 远程服务接口 | 通过请求调用模型，受服务条款和定价约束 |
| 开放权重 | 可下载的模型参数及相关组件 | 按许可证自行部署、研究或微调 |

⚠️ **开放权重不等于完整开源。** 训练代码、训练数据、数据处理过程可能没有公开，许可证也可能限制用途或商用。

#### 开放权重的价值

- **自主部署**：模型可部署在本地或自有服务器；本地推理可以减少数据对外传输。
- **定制能力**：**微调是利用特定数据继续训练模型，使其更适应某类任务**，例如领域术语客服、专业文档处理。
- **研究与检查**：便于独立评测、研究模型内部行为和安全问题；但拿到权重并不意味着能证明模型不存在后门。
- **生态建设**：开发者围绕模型构建工具、产品和服务，厂商可通过云服务、定制与企业支持获得收入。
- **技术自主**：降低对单一远程服务供应商的依赖，但仍受硬件、配套软件和许可证约束。

#### 成本与边界

⚠️ **开放权重不等于零成本使用。** 部署成本包括**显存、算力、电力、存储和维护**。模型大小、精度、量化方式、上下文长度、并发量都会影响硬件需求。

> **参数量**：模型包含的参数数量。`B` 表示十亿，`T` 表示万亿。
> **总参数量与激活参数量不同**：部分稀疏模型每次计算只使用一部分参数，但存储仍需考虑全部权重。

闭源 API 通常不能直接修改底层权重，但部分服务支持托管微调。**模型选择应结合任务、成本、部署条件和许可证，而不是只看开放程度。**

### 2. 多模态模型

#### 基本概念

> **模态**：信息的表达形式，如文本、图像、音频和视频。代码、表格也可作为具体的数据形式，但不一定被视为独立的感知模态。

**多模态模型**：能够处理多种信息形式，并在它们之间建立关联的模型。

⚠️ **支持多模态输入，不代表一定支持多模态输出** —— 理解图片的模型未必能生成图片。

- **向量**：按顺序排列的一组数值。
- **嵌入（Embedding）**：将输入编码为便于计算和比较的向量表示。
- **统一嵌入空间**：将不同模态映射到可进行关联比较的表示空间。例如"猫"的文本、猫的照片、猫叫声可能具有相近的语义表示。多模态模型的具体架构有多种，并非都只靠一个统一向量空间实现。

💡 **嵌入模型与生成模型不同**：嵌入模型主要用于**检索、匹配和分类**；生成模型用于**产生文本、图像、音频**等内容。

#### 常见应用

| 应用 | 输入与结果 | 关键能力 |
|---|---|---|
| 截图理解 | 报错截图 → 问题定位；菜单截图 → 翻译 | 文字识别、视觉理解与问答 |
| 对话式改图 | 原图 + 修改描述 → 修改后的图像 | 图像编辑、指令理解 |
| 视频分析 | 视频 → 分镜、剧情摘要、片段定位 | 时序理解与画面分析 |
| 语音交互 | 语音 → 理解与语音回复 | 音频理解、语言处理与语音生成 |
| 跨模态检索 | 文字描述 → 对应图片或视频片段 | 文本与视觉内容的语义匹配 |
| 软件操作 | 屏幕内容 → 操作决策与工具调用 | 视觉定位、规划与执行 |

> **OCR**：把图像中的文字识别成可处理的文本。多模态模型可以结合画面和文字理解，但具体系统仍可能使用 OCR。

**智能体（Agent）**：围绕目标进行规划、调用工具、执行操作并根据结果继续行动的系统。多模态能力有助于理解屏幕；实际点击、输入等动作还需要执行工具。智能体也可以通过 API 工作，不必依赖视觉操作。

#### 使用边界

⚠️ **幻觉**：模型产生看似合理、但缺少事实依据或与输入不符的内容。图片中的细节、视频时序和声音内容都可能被误判。

不同模态的能力并不均衡；长视频和长音频通常增加处理成本与延迟。**关键判断应回到原图、原视频、原音频或其他证据核对。**

### 3. 专业能力与作品积累

#### 能力成长框架

```
领域知识 + 个人能力 → 实用作品 → 真实使用 → 反馈迭代 → 可展示成果
```

> **反馈闭环**：交付作品、收集真实使用结果、分析问题、修改作品，再验证效果的循环。迭代次数不是固定要求，重点在于**根据证据持续改进**。

> **判断力**：识别问题价值、设定优先级、选择解决方式的能力。**熟练掌握工具**与**判断问题是否值得解决**，是不同的能力。

- **作品证据**：能够被外部检查的成果，如产品、代码仓库、文章、案例和使用反馈。作品的价值既包括是否完成，也包括是否解决了实际问题。
- **分发能力**：让目标使用者发现、理解并使用成果的能力。学习和开发可以同步关注使用场景、目标人群及发布渠道。

#### 实践路径

1. 选择一个**范围小、需求明确**的问题。
2. 学习完成任务所需的知识，做出**可使用的最小作品**。
3. 让目标使用者试用，记录实际问题。
4. 按影响排序修改，并检查效果。
5. 保存作品、过程记录与结果，形成可复用的经验。

> **游戏领域示例**：理解游戏机制 → 学习地图或 MOD 制作 → 制作一张地图 → 发布 → 根据玩家反馈改进。

#### 观点与事实的区分

"AI 工具降低制作门槛、使判断力和分发更重要"属于**对趋势的判断**；具体程度取决于任务和领域。

"改三轮才能形成闭环""知名度带来几十倍差距"等说法 **不作为固定规律记忆**。

### 4. 开源协议与使用限制

#### 4.1 判断协议的基本概念

> **许可证（License）**：权利人授予使用、修改、复制或分发权限，并规定条件的法律文本。

- **开源软件**：不仅公开源代码，还通过符合开源定义的许可证允许使用、修改和再分发。⚠️ 单纯公开代码、开放下载或允许研究，**并不自动构成开源**。
- **宽松许可证**：通常允许将代码用于闭源产品，主要要求保留许可证和相关声明。
- **Copyleft**：通过许可条件要求特定范围内的修改或衍生作品继续保留相应自由。⚠️ Copyleft **不等于禁止商用**，也不等于必须免费提供产品。
- **源码可见（Source-Available）**：可以查看源代码，但许可可能限制生产使用、托管服务或其他用途。
- **分发**：将软件或其副本交付给其他主体。
- **SaaS**：通过网络提供软件功能的服务方式。

💡 **分发软件**与**提供网络服务**，是不同的许可触发场景。

**判断维度**：商用是否允许、义务何时触发、源码提供范围、专利与商标规则、规模或用途限制。

#### 4.2 常见软件许可证速查

| 许可证 | 商用 | 源码义务与主要条件 |
|---|---|---|
| `MIT` | 允许 | 通常可闭源使用；复制或分发时保留版权与许可声明；无明确专利授权条款 |
| `BSD-2-Clause` | 允许 | 通常可闭源使用；保留版权、许可条件与免责声明 |
| `BSD-3-Clause` | 允许 | 在 BSD-2 基础上，不得未经许可用作者或贡献者名称为衍生产品背书 |
| `Apache-2.0` | 允许 | 可闭源；附许可、保留相关声明、标明修改；原作品有 NOTICE 时保留适用的归属声明；含明确专利授权 |
| `MPL-2.0` | 允许 | 分发时，受 MPL 覆盖的文件及其修改需按 MPL 提供源码；独立文件可采用其他许可 |
| `LGPL` | 允许 | 库及其修改受相应许可约束；应用可在满足链接、替换或重新链接等要求的情况下闭源；具体看版本 |
| `GPL v2/v3` | 允许 | 对分发的受 GPL 覆盖作品提供对应源码及相应权利；是否构成一个衍生或组合作品决定范围 |
| `AGPL-3.0` | 允许 | 除 GPL 类义务外，修改版本与用户通过网络交互时，需向这些用户提供获取对应源码的机会 |

🔍 **两个常见误解**：

- **GPL 不要求把任何使用它的"整个项目"一律公开。** 独立程序、单纯聚合、链接关系和衍生作品需要分别判断；源码提供义务通常针对**接收者**，并不必然要求向全世界公开。
- **AGPL 不等于所有提供网络服务的代码都要开源。** 网络条款针对许可覆盖的**修改版本及其对应源码**，外围独立系统的边界仍需具体判断。

- **动态链接与静态链接**：分别在运行时或构建时把程序与库连接起来的方式。LGPL 下两者都需满足相应条件；**静态链接通常需要额外提供可重新链接的材料**。
- **专利授权不等于覆盖所有第三方专利风险**。Apache-2.0 的授权范围限定于贡献者可授权、且相关贡献必然涉及的专利权利要求；符合条款规定的专利诉讼会终止相关专利许可。商标许可也不由该协议普遍授予。详见 [Apache-2.0 正文](https://www.apache.org/licenses/LICENSE-2.0)。
- MPL 的文件级边界见 [Mozilla 官方 FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/)。
- **Tivoization**：设备提供了源码，却通过技术限制阻止用户运行修改后的版本。GPLv3 对特定"用户产品"的安装信息设有要求，并非无条件禁止所有硬件限制。

#### 4.3 文字、图片与素材：Creative Commons

> **Creative Commons（CC）**：主要用于内容作品的一组公共许可证，**通常不用于软件代码**。常见限制元素为 BY、NC、ND、SA。

| 元素 | 含义 |
|---|---|
| **BY（署名）** | 按条款提供作者、来源与许可等信息 |
| **NC（非商业性使用）** | 许可范围限制为非商业性使用 |
| **ND（禁止演绎作品分享）** | 不允许分享改编后的材料；并非禁止一切私人修改或格式转换 |
| **SA（相同方式共享）** | 分享改编作品时采用相同或兼容的许可 |

| 工具或许可证 | 商用 | 修改与分享条件 |
|---|---|---|
| `CC0` | 通常允许 | 尽可能放弃版权及相关权利，并提供许可兜底；不是所有权利都能被放弃 |
| `CC BY` | 允许 | 可改编和分享，需署名并履行相关声明义务 |
| `CC BY-SA` | 允许 | 署名；分享改编作品时遵守 SA |
| `CC BY-NC` | 不授予商业性使用权限 | 署名；限定非商业性使用 |
| `CC BY-NC-SA` | 不授予商业性使用权限 | 署名；限定非商业性使用；分享改编作品时遵守 SA |
| `CC BY-ND` | 允许分享未改编材料，包括商用 | 署名；不分享改编后的材料 |
| `CC BY-NC-ND` | 不授予商业性使用权限 | 署名；限定非商业性使用；不分享改编后的材料 |

ND 的准确边界见 [CC BY-ND 4.0 官方说明](https://creativecommons.org/licenses/by-nd/4.0/)。

> **CDLA（Community Data License Agreement）**：面向数据共享的许可体系。不同许可与版本的义务不同，**不能仅按名称判断**。

#### 4.4 源码可见许可证

| 许可证 | 主要限制与边界 |
|---|---|
| `SSPL` | 将相关软件功能作为服务提供给第三方时，可能要求公开广泛的服务配套源码；**不能等同于标准开源许可** |
| `Business Source License`（BUSL/BSL） | 通常允许非生产用途；生产用途取决于额外授权；到规定变更日期按指定的开源许可证转换 |
| `Elastic License 2.0` | 限制提供使第三方访问软件实质功能的托管或管理服务；禁止绕过许可密钥和移除相关声明 |

Elastic License 2.0 的官方说明列出三类限制，**没有**原对话所述的一般性"禁止训练其他产品"条款。见 [Elastic 官方 FAQ](https://www.elastic.co/licensing/elastic-license/faq)。

#### 4.5 模型权重的许可证

⚠️ **四个不同问题**：代码许可证、权重许可证、数据集许可证、输出内容的权利。**代码采用 MIT 或 Apache-2.0，不代表同仓库的权重也适用相同许可。**

| 条款类型 | 对使用范围的影响 | 原对话中的例子 |
|---|---|---|
| 用户规模门槛 | 达到指定规模后需额外授权 | 部分 Llama Community License |
| 营收门槛 | 免费商用范围取决于营收条件 | Stability AI 部分模型许可 |
| 用途限制与下游继承 | 禁止特定用途，衍生或再分发模型可能需保留限制 | RAIL / OpenRAIL 系列 |
| 研究或非生产用途 | 评测、研究可用，但生产部署未获授权 | Mistral 部分历史模型许可 |
| 非商业许可 | 不授予商业性使用权限 | 部分采用 CC BY-NC 的权重 |
| 自定义使用条款 | 另有使用限制、声明或再分发要求 | Gemma Terms 等 |

> ⚠️ 以上为**条款类型与原对话示例**，不作为当前具体型号许可的结论。模型代际、型号、版本不同，条款及门槛可能不同。

#### 4.6 使用前的核对顺序

1. 确定**具体组件、版本**和对应 `LICENSE`，区分代码、权重、数据与素材。
2. 明确使用方式：内部运行、修改、交付副本、嵌入产品或提供网络服务。
3. 检查**商用、用户规模、营收、生产用途和禁止用途**条款。
4. 确认源码提供范围、下游继承要求、版权声明、修改标记和 NOTICE。
5. 分别核对**商标、专利及输出内容相关权利**。

💡 MIT、BSD、Apache-2.0 等通常更便于闭源集成，但仍有声明和许可义务。AGPL、NC 或自定义条款的使用范围不同，**不能简单归为"不能用"**。

### 5. 复习要点

| 问题 | 核心答案 |
|---|---|
| 权重是什么？ | **训练得到的数值参数**，运行还需要架构与配套组件 |
| 开放权重意味着免费、无限制吗？ | 不意味着；部署有成本，许可有条件 |
| 多模态是什么？ | **处理并关联多种信息形式的能力** |
| 嵌入有什么作用？ | **将输入变成向量表示**，便于检索、匹配和比较 |
| 做出作品后如何积累能力？ | 真实使用、反馈、修改、验证，形成**反馈闭环** |
| 开源与商用是否矛盾？ | 不矛盾；常见开源许可证允许商用，但有不同义务 |
| GPL 与 AGPL 的关键区别？ | GPL 重点关注**分发**；AGPL 另有针对**修改版本网络交互**的源码提供要求 |
| 权重开放最容易漏看什么？ | **权重独立许可、规模与营收门槛、用途限制和下游义务** |
